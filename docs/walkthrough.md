# Ручной прогон на dev-боте (SPEC REQ-TEST-5)

Перед релизом. Каждый шаг — что сделать и что должно быть видно.

0. До первого запуска подготовить оба монтируемых каталога: `./data` и каталог, который монтируется в `/claude` — по умолчанию `~/.claude-telegrind`, либо тот, что задан в `TELEGRIND_ACCOUNT_DIR`: `mkdir -p ./data ~/.claude-telegrind && chown -R 1000:1000 ./data ~/.claude-telegrind` (или `sudo chown`; при своём `TELEGRIND_ACCOUNT_DIR` — его путь вместо `~/.claude-telegrind`). Иначе Docker создаст каталоги от root, бот не сможет писать, а `doctor` покажет «NOT OURS». `docker compose` запускать от имени оператора, не через `sudo`: под `sudo docker compose` тильда в значении по умолчанию `~/.claude-telegrind` раскроется в домашний каталог root, и бот получит пустой чужой каталог. Если без `sudo` нельзя — задать `TELEGRIND_ACCOUNT_DIR` абсолютным путём.
1. `docker compose up -d --build` → `docker compose exec bot telegrind doctor`: claude и sqlite3 с версиями, владелец каталогов — наш uid, `claude token: set`.
2. Первый вопрос — это проверка токена. В проде агент входит по `CLAUDE_CODE_OAUTH_TOKEN` в пустой каталог аккаунта; живой гейт на dev-машине работал на скопированных учётных данных, так что этот путь до деплоя не измерен, и первый настоящий ответ на latitude — и есть измерение. Сообщение «сколько записей в журнале» и ❤ на него → 👀 → ответ. Если вместо ответа «Не получилось ответить» или ошибка входа в логе (`docker compose logs bot`) — токен не работает: остановиться и разбираться до остальных шагов.
3. Текст «4500 такси» → 💔 на сообщении; в `users/<id>/log.sqlite` одна запись, `revision` 1.
4. Правка текста → 💔 сменился на ❤‍🔥; `revision` 2; оба текста в `events`.
5. Удаление: тап по 💔 бота (твоя реакция — то же сердце) → `deleted_at` выставлен; восстановление: снять реакцию → сброшен; повторная реакция ничего не пишет. 👍 и ❤ ничего не удаляют; ❤ (двойной тап по умолчанию) обращает сообщение к боту.
6. Фото чека → 💔, через секунду файл в `media/<sha256>`, `media_sha256` в записи. Фото с подписью «сколько тут?» → только 💔: знак вопроса ничего не значит. Двойной тап (❤) по нему → 👀 → 💔 снято, `addressed_at` выставлен → ответ про то, что на фото (ход ждёт загрузки файла). Снять ❤ → 💔 вернулось, запись снова в журнале.
7. Голосовое «вес восемьдесят два и четыре» → 💔, затем цитата «🎙 вес 82.4» ответом на голосовое; `transcript_raw` и `transcript` в записи.
8. Голосовое «сколько я потратил на такси» → цитата и 💔, хода нет. ❤ на цитату бота (или на само голосовое) → 👀 → ответ с числом из SQL; 💔 с голосового снято, фактов из него нет.
8a. Ответь голосом на ответ бота («а за сентябрь?») → цитата, затем 👀 → ответ в той же сессии (агент помнит, о чём шла речь); 💔 с голосового снято.
9. Текст «такси 500» → 💔; потом «вчера было не 500, а 5000» ответом на него и ❤ на ответ → агент исправляет строку той записи и говорит, что сделал. Ответ на ответ бота продолжает ту же сессию (один `--resume`).
10. Проход по расписанию. Второй процесс проход не запустит: `Engine` бота держит блокировку на `DATA_DIR/state`. Поэтому проход вызывается настройкой, на которую бот реагирует сам. Вопросы в шагах 8–9 уже разобрали хвост, так что сначала нужен новый: отправить две обычные записи («1200 такси», «300 кофе») и убедиться в `docker compose exec bot telegrind doctor`, что `unprocessed` не меньше 2. Затем одно из двух:
    - в `.env` поставить `QUIET_HOUR` равным текущему часу по часам человека (зона из `settings.tz` в `facts.sqlite`, иначе `DEFAULT_TZ`) — проход стартует на ближайшем тике планировщика (до минуты), но только если в журнале `turns` за сегодня ещё нет прохода; для второго прогона в тот же день — второй способ;
    - либо `BACKLOG_LIMIT=1` — проход стартует на записи, после которой необработанных больше одной: после перезапуска отправить ещё одну запись.

    После правки `.env` — `docker compose up -d` (контейнер пересоздаётся; `docker compose restart` `.env` не перечитывает). Перед этим снять `sqlite3 log.sqlite "SELECT message_id, revision, deleted_at FROM entries ORDER BY message_id"`. → строка-итог в чате только если `processed` изменился; `facts.sqlite` с типизированными таблицами, `entry_id` и `at` в каждой; тот же запрос к `log.sqlite` после прохода даёт те же строки плюс строку итога. sha256 файла `log.sqlite` не сравнивать: Python сам дописывает строку в `turns` и итог. Затем вернуть прежнее значение в `.env` и снова `docker compose up -d`.
10a. «напомни через 5 минут проверить чайник» с ❤ → агент отвечает, когда напомнит; в `reminders` строка с `time`. Через 5 минут (до минуты сверху) приходит «⏰ проверить чайник» ответом на просьбу; второго нет. Ответ «отмени» на ежемесячное напоминание → `done = 1`.
11. Перезапуск бота во время вопроса (`docker compose restart bot`) → контейнер останавливается сразу (SIGTERM — немедленный выход, без ожидания ответа); в логе нового запуска «stranded … forgotten», запись осталась необработанной, вопрос не переспрашивается.
12. `/start` → ответ Аиши, в женском роде; `/q` ничего особого не значит и тоже доходит до неё целиком.
13. Сообщение с чужого аккаунта → ничего: ни строки, ни реакции.
14. Кнопка-предложение (REQ-TURN-13, REQ-TRIGGER-6). Вопрос, на который Аиша отвечает предложением («покажи траты за месяц» — и она предлагает что-то записать или сделать) → под ответом одна кнопка [Да]. Нажать → кнопка сменилась на «✓ Да», 👀 на ответе бота, затем Аиша делает предложенное. В `log.sqlite` у записи бота (`author = 'bot'`): `sqlite3 log.sqlite "SELECT kind, payload FROM events WHERE message_id = <id ответа> ORDER BY id"` → `control` (с `block`, `poll_id` пуст), `pressed` (`data`, `update`), `answered`. Повторный тап по уже отмеченной кнопке ничего не запускает: `SELECT kind FROM events WHERE message_id = <id ответа> ORDER BY id` заканчивается `pressed, answered, pressed` — второго `answered` нет, нового хода и 👀 тоже. Если суточная квота человека исчерпана, нажатие всё равно закрывает кнопку и ставит «✓ Да», а ход отвечает текстом про квоту — это не сбой.
15. То же предложение, но ответить ответом на сообщение текстом «да, давай» (REQ-TRIGGER-7) → кнопка стала «✓ ответ текстом», обычный ответный ход. В событиях записи бота `closed` с `{"how": "text"}`, и он записан раньше любого вызова Telegram; `answered` нет. Повторное нажатие уже снятой кнопки (если клиент ещё показывает старую) ничего не запускает: в событиях добавляется только `pressed`, нового `answered` и нового хода нет.
16. Вопрос с выбором из нескольких вариантов («на какой счёт записать?») → за ответом отдельным сообщением идёт опрос, ответом на ответ. В `log.sqlite`: у записи опроса `text` — опрос нумерованным текстом, у ответа перед опросом `control` нет; `control` с непустым `poll_id` есть только у записи опроса, и `SELECT * FROM polls` содержит этот `poll_id` и `message_id` записи опроса. Проголосовать → опрос остановлен (закрыт), 👀, Аиша применяет выбор («Выбрано в опросе: …»); события `voted` и `answered`. Отозвать голос («Retract vote») и переголосовать нельзя: после засчитанного голоса опрос закрыт. Если Telegram отверг опрос, вопрос приходит нумерованным текстом ответом на ответ, без `control`: текстовый ответ на него продолжает цепочку как обычный ответ. Пустой голос (отозванный до засчитывания) пишется как `voted`, ход не запускает и опрос оставляет открытым.
17. Тот же опрос, но вместо голоса ответить на него текстом → опрос остановлен, в событиях записи опроса `closed` с `{"how": "text"}`; Аиша отвечает на этот текст в той же сессии (помнит, о чём шла речь), без `voted`.
18. Знакомство (REQ-CONTRACT-16). Сохранить копию `users/<id>/CLAUDE.md` и убрать из него раздел «## О человеке». `/start` → Аиша спрашивает «Как к вам обращаться?» формой из двух рядов кнопок-галочек (`ты | вы`, `он | она`) и [Готово]; заранее ничего не отмечено, и пока так, к человеку обращаются на «вы», без рода. Нажать на пару кнопок → галочки переставляются, ходов нет, в событиях только `pressed` (`data`, `update`) без `answered`. `docker compose restart bot`, затем нажать ещё одну галочку: ранее отмеченные остаются на месте (они переигрываются из `pressed`). Дальше один из двух путей, второй — после повтора с начала шага (снова убрать раздел, `/start`):
    - кнопкой: отметить `ты` и `он` (или `она`), нажать [Готово] → клавиатура сменилась на одну кнопку «✓ Готово», 👀 на сообщении с формой, затем ответ Аиши ответом на это сообщение. В событиях записи формы `control`, несколько `pressed` (последний — [Готово]), `answered`; `closed` нет. Вход хода: «Анкета: ты; он» (по строкам в их порядке, «не выбрано» для строки без отметки), без строки «Текстом». В `CLAUDE.md` раздел «## О человеке» с обращением и родом, следующий ответ — на «ты» и в выбранном роде. Повторное нажатие [Готово] (если клиент ещё показывает старую клавиатуру) ничего не запускает: добавляется только `pressed`;
    - текстом: ответить на форму текстом с именем → кнопки сменились на «✓ ответ текстом», форма закрыта (`closed` с `{"how": "text"}`, `answered` нет), вход хода: «Анкета: …; …\nТекстом: …» с уже отмеченными галочками. В `CLAUDE.md` появляется раздел «## О человеке» с именем; если `ты | вы` не отмечено, в разделе записано «на вы».

    Вернуть сохранённую копию. Если в ней «## О человеке» ничего не говорит о «ты» или «вы» — следующий ответ на «ты», и формы знакомства нет.
19. Подмена (REQ-TURN-13, REQ-LOG-9). Подмена закрывает открытую кнопку, на которую не отвечали, когда в той же цепочке приходит более новый ответ — но не через ответ на само сообщение с кнопкой (это шаг 15: `closed` с `{"how": "text"}`). Поэтому нужна развилка в цепочке:
    1. Задать вопрос, на который Аиша отвечает без кнопок («сколько я потратил на такси») → ответ A1, без клавиатуры.
    2. Ответить на A1 вопросом, на который она отвечает предложением с [Да] (как в шаге 14) → ответ A2 с кнопкой [Да]. Не нажимать.
    3. Снова ответить на A1 (не на A2) любым вопросом («а за сентябрь?») → 👀, ответ A3. У A2 кнопка [Да] пропала (клавиатура снята, без «✓»). `sqlite3 log.sqlite "SELECT kind, payload FROM events WHERE message_id = <id A2> ORDER BY id"` → `control`, а после него `closed` с `{"how": "superseded"}`; `pressed` и `answered` нет. Если у A3 своя кнопка или опрос — они остаются открытыми: у записи A3 (или его опроса) `control` без `closed`.
    4. Подмена — только внутри цепочки. Если до пункта 3 получить ещё одну кнопку [Да] отдельным новым вопросом (не ответом на сообщение бота), после пункта 3 она на месте и в её событиях нет `closed`.
